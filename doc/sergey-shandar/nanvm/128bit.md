# 128bit VM for high-level languages

128-bit VM is designed for languages where we can't create NaN-based tag-pointers in 64-bits. The idea is to have enum (1 byte) and 15 bytes payload.
For example:

```rust
enum Any {
    Null,
    Undefined,
    Number(f64),
    Bool(bool),
    String(Rc<String16>),
    Bigint(Rc<Bigint>),
    Object(Rc<Object>),
    Array(Rc<Array>),
    Function(Rc<Function>),

    // Thin pointers: a static type is sized and carries its own length.
    StaticString16(&'static StaticString16),
    StaticAscii(&'static StaticAscii),
    StaticBigint(&'static StaticBigint),
    StaticObject(&'static StaticObject),
    StaticArray(&'static StaticArray),
    StaticFunction(&'static StaticFunction),

    // The tag is the length, so no payload byte is spent on it.
    ShortStr0,
    ShortStr1([u16; 1]),
    // ...
    ShortStr7([u16; 7]),
    ShortAscii8([u8; 8]),
    // ...
    ShortAscii15([u8; 15]),

    ShortBigint(i64),
}
```

Only the short strings use all 15 bytes. A variant that holds `f64`, `i64` or a pointer has 8 bytes, at offset 8.

A static pointer is a plain field, so ordinary load-time relocation works. The 64-bit NaN-pointer needs [a workaround](./rebase.md).

## Short strings

Each string has exactly one representation. Otherwise, equality and hashing have to compare across variants. The length decides first, then the alphabet:

|Length |Variant                        |Alphabet                   |
|-------|-------------------------------|---------------------------|
|`0..7` |`ShortStr0`..`ShortStr7`       |any UTF-16                 |
|`8..15`|`ShortAscii8`..`ShortAscii15`  |all code units are `< 0x80`|
|other  |`String` or a static string    |                           |

16 variants. A string of up to 7 code units needs no ASCII scan. Equality of two short strings is one 16-byte compare, with no hash and no global table of interned strings.

Options:

- `ShortAscii` can be Latin-1 for free: the bytes are 8 bits already, so the rule becomes "all code units are `< 0x100`".
- 6-bit characters (`a-z`, `A-Z`, `0-9`, `_`, `$`: a JS identifier) extend the length to 20, because the payload is 120 bits. The price is a shift and a mask for each character, and five more variants. 15 already covers almost all property keys.

For comparison, the longest short string in a NaN-pointer is 8 characters of 6 bits. See [Low Level](./README.md).

## Languages

Each language can have two values: 64 bits or 128 bits.

|Group                               |Languages                                              |64 bits                |128 bits                             |
|------------------------------------|-------------------------------------------------------|-----------------------|-------------------------------------|
|raw memory                          |C, C++, Rust, Zig, D, Nim, WebAssembly (linear memory) |NaN-pointer            |tag (1 byte) and payload (15 bytes)  |
|value structs with traced references|Swift, C#, F#, Go                                      |boxed                  |a reference and 64 bits (Swift: tag and 15 bytes)|
|no value structs                    |Java, Kotlin, Scala, Dart, OCaml, Haskell, WebAssembly GC|boxed                |only in containers, as parallel arrays|
|dynamic host                        |JavaScript, Python, Ruby, PHP, Lua                     |the host's value       |                                     |

The split is a capability, not a language: can we forge pointer bits, can a struct hold a reference inline, or neither.

Existing JS engines: SpiderMonkey, JavaScriptCore and Hermes use 64 bits; V8 uses 32 bits in a heap with pointer compression (an offset from a base, like [option 3](./rebase.md#options)) and 64 bits without it; QuickJS and Duktape use 128 bits on 64-bit platforms and a NaN-pointer on 32-bit platforms. None of them keeps the characters of a short string in a value.

### Swift

An enum is already a tag and the largest payload. The tag is placed after the payload, so a payload of up to 15 bytes gives 16 bytes.

```swift
enum Any {
    case null
    case undefined
    case number(Double)
    case bool(Bool)
    case string(String16) // a class, ARC is Rc
    // ...
    case staticString16(UnsafePointer<StaticString16>)
    // ...
    case shortStr7(InlineArray<7, UInt16>)
    case shortAscii15(InlineArray<15, UInt8>)
    case shortBigint(Int64)
}
```

`InlineArray` needs Swift 6.2. Before it, the payload is a tuple.

### C#

An explicit layout can't overlap a reference with other fields, so the reference has its own word and it is the tag as well. The payload is 64 bits, not 15 bytes.

```csharp
readonly struct Any
{
    readonly object? _ref; // a heap object, or a sentinel that is a tag
    readonly ulong _bits;  // f64, i64, or a packed short string

    static readonly object UndefinedTag = new(), NumberTag = new(),
                           BoolTag = new(), ShortBigintTag = new();
    static readonly object[] ShortStrTag = NewTags(5);    // the index is the length, 0..4
    static readonly object[] ShortAsciiTag = NewTags(10); // the index is the length, 5..9

    public bool IsNull => _ref is null;
    public bool IsNumber => ReferenceEquals(_ref, NumberTag);
    public bool IsString => _ref is String16; // the runtime type is the tag
}
```

- Short strings: `0..4` code units of UTF-16, then `5..9` characters of 7-bit ASCII.
- No `Static*` variants. The GC doesn't distinguish static and heap objects.
- A C# 15 `union` is one `object?`: 64 bits, and each number is boxed. A hand-written struct can be marked as a custom union to have an exhaustive `switch` with no boxing.

### Java

A `record` is a heap object, so there is no 128-bit value to pass or return. A container can hold two parallel arrays, `Object[]` and `long[]`, where one index is one value.

## 64 or 128

Two beliefs:

1. Dereferencing is one of the most expensive operations: a cache miss costs hundreds of cycles, and with reference counting, a clone or a drop writes to the header of the object.
2. A value that fits into a register (64 bits) is cheaper. The larger part of the cost is in containers: half as many values fit in a cache line.

They pull in opposite directions. 128 bits removes dereferences because more strings and bigints are inline. 128 bits adds cache misses because each container is twice as big. Arrays of numbers and references favour 64 bits. Objects with keys of `9..15` characters favour 128 bits.

So:

- NaN-pointer where the language allows it.
- 128 bits where it doesn't, instead of boxing: a number never allocates. Boxed is the baseline for languages with no value structs.
- In Rust, the 128-bit enum needs no `unsafe`. It can be a reference implementation to test the NaN-pointer against.
- Start with numbers, booleans, `null`, `undefined` and `ShortBigint`. A benchmark on real programs should confirm the rest.
