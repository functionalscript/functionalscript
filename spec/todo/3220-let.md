# Let statement

**Priority:** P2
**Status:** wip — the one-variable loop landed; the rest is open

Introducing `let` and `=`.

```js
export default () => {
    let a = 0
    a = 'Hello world!'
    return a
}
```

## What landed

The one-variable loop, `let x = init;` followed by `while (condition) { … }`
with `const`s and assignments to `x` in its block, is in the language
([loops](../README.md#loops)). It is sugar over the EDAG's own function
and call: the template `fjs/edag/loop` recognizes,
`['=>', 1, slots, ['?:', c, ['()', ['self'], [next]], ['arg', 0]]]`, called
with the initial value, so the graph is the one a hand-written recursive
function of that shape has, and every writer that recognizes the template
spells it as a loop again
([tail-call-loop](../../fjs/edag/todo/tail-call-loop.md)). Three refusals
keep the reading JavaScript's: a nested function reading the variable, a
`const` of its name in the block, and an assignment to any other name.

Approved for that form by `sergey-shandar`, the language designer, who
directed the design and the implementation in the session of the pull
request that landed it
([#2852](https://github.com/functionalscript/functionalscript/pull/2852)'s
stack).

## Open

- A `let` outside a loop, the example above: a rebinding, with no node of
  its own.
- Several variables in one loop: the function over all of them, its exit
  the array of their values, each read from it after the loop.
- `break` and `continue` in the block, `while (true)`, `for`, and a guard,
  `return` or `throw` in the block: the arm the call stands in is then
  either, and the serializer todo's general rule — every reference to
  `self` the callee of a call in tail position — replaces the template.
- A loop at the module level, the module being a function too.
- The Rust output's `loop` form ([tail-call-loop](../../fjs/edag/todo/tail-call-loop.md)).
