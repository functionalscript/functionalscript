# Let statement

**Priority:** P2
**Status:** proposed — awaiting the language designer's approval; the
implementation is
[#2854](https://github.com/functionalscript/functionalscript/pull/2854),
which lands only once the approval is recorded below

Introducing `let` and `=`, in one form first: the loop over one variable.

```js
export default n => {
    let r = 1;
    while (r < n) { r = r * 2; }
    return r;
};
```

## Problem

FunctionalScript expresses a loop one way: a `const` whose function calls
itself. Both serializers spell that as recursion, and V8 and Rust implement
no tail calls, so every loop a program writes overflows the stack after some
thousands of rounds in every output. The serializers can spell a tail
self-call as a loop again
([tail-call-loop](../../fjs/edag/todo/tail-call-loop.md)), which fixes the
functions written that way; it does not give the language a loop a reader
recognizes as one.

## Proposal

Two statements of a block body, standing where a `const` may, that the
compiler reads as one loop — exactly the template the serializers
recognize, and nothing more:

```
statement ::= const | 'if' '(' value ')' block
            | 'let' id '=' value end | 'while' '(' value ')' loopBlock
loopBlock ::= '{' loopStatement* '}'
loopStatement ::= const | id '=' value end
```

- `let x = init;` declares the loop's variable with its initial value, and
  the `while` right after it runs its block while the condition is truthy,
  tested before each round as `?:` tests its condition.
- The block holds `const`s and assignments to the variable, `x = value;`.
  An assignment rebinds the variable for the statements after it, in
  order; the block's end continues the loop with the last binding, the
  variable unchanged where nothing assigned it.
- From the loop on, `x` is a `const` of the body holding the value the last
  round left.
- One variable per loop, the `while` right after its `let`, no `break`,
  `continue`, guard, `return`, `throw` or nested loop in the block, no
  `let` anywhere else, no loop at the module level. Each is a later step,
  additive on this one, under [Later](#later).

**Lowering.** The loop is syntactic sugar and adds no node: `let r = init;
while (c) { s…; r = next; } rest` denotes `rest` with `r` the value of
`loop(init)`, where `loop` is `r => c ? (() => { s…; return loop(next);
})() : r` — the recursive spelling, its one parameter the variable, the
block the body of a parameterless function called where it stands, as a
guard's block is, so that a `const` in it is the block's alone and runs
only when the condition holds. The graph is the template
`['=>', 1, slots, ['?:', c, ['()', ['self'], [next]], ['arg', 0]]]` called
with `init`, a comma around the call where the block holds a `const` the
next value does not reach: the graph and hash a function written that way
has, and what the block reads from the body around it is the function's
frame, as any nested function's captures are.

**Refusals.** Three programs JavaScript admits are refused rather than
read another way, each because this reading and JavaScript's would
differ:

- a function nested in the loop, in its condition or its block, that reads
  the variable: JavaScript's closure sees the variable's last value, where
  the function's capture would hold the value of the round it was made in;
- a `const` of the variable's name in the block: JavaScript's block
  binding, which the loop never sees, where this reading would take it for
  the assignment the block's end continues with;
- an assignment to any other name, the one name a block may rebind.

A `let` not followed by its `while`, or a `while` no `let` stands before,
is refused: the two are one loop. The variable is a name of the body as a
`const` is.

**Writers.** The source writer spells the template, called where it is
written in a function body, as the two statements, so a compiled module
runs in constant stack; the function text spells the template function as
the same `let` and `while` over a `let` of its parameter. Every writer has
the one loop spelling or the recursion, nothing else
([tail-call-loop](../../fjs/edag/todo/tail-call-loop.md)). The round trip,
`while` source to EDAG to `while` source to the same EDAG, is the proof
that the lowering and the spelling are inverses.

### Benefits

- A loop that reads as one, in the JavaScript spelling every reader knows,
  and that runs the same under Node, in the compiled module and through the
  VM — no spelling a JavaScript engine reads differently is admitted.
- Constant stack in every output that recognizes the template, where the
  recursive spelling overflows on V8 and in Rust.
- No new node: the EDAG, its validators, interpreters and hash are
  untouched, and a hand-written tail-recursive function and the loop are
  one graph.
- The restriction to one template keeps the parser's lowering and the
  writer's recognizer inverses by construction, so the round trip is exact
  rather than argued.

### Drawbacks

- The form is narrow. A loop over two variables, an early exit, or a
  `let` on its own are JavaScript the compiler refuses today, each for a
  later step rather than read another way.
- `let` means one thing only, the loop's variable; a JavaScript module
  using it elsewhere is refused.
- The text of a template function is program-visible, `String(f)`, and
  changes from the named function expression to the loop
  ([tail-call-loop](../../fjs/edag/todo/tail-call-loop.md)).
- Until the Rust output has its loop form, a compiled Rust module still
  recurses.
- Two keywords, four grammar rules, four frames in the fold, and one
  statement form in the writer: the complexity is the fold's, and it is
  bounded by the template.

## Later

- A `let` outside a loop: a rebinding, with no node of its own.
- Several variables in one loop: the function over all of them, its exit
  the array of their values, each read from it after the loop.
- `break` and `continue` in the block, `while (true)`, `for`, and a guard,
  `return` or `throw` in the block: the arm the call stands in is then
  either, and the serializer todo's general rule — every reference to
  `self` the callee of a call in tail position — replaces the template.
- A loop at the module level, the module being a function too.
- [Mutability](./mutability.md) treats `let` as its zero stage; the further
  stages are its own.
