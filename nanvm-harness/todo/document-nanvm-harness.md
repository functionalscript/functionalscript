## Document nanvm-harness

**Priority:** P4
**Status:** open

### Problem

[AGENTS.md](../../AGENTS.md) and [CONTRIBUTING.md](../../CONTRIBUTING.md)
both open with "a monorepo with two code bases", `fjs/` and `nanvm-lib/`, and
neither mentions this crate. Yet `nanvm-harness` is the second member of the
root [`Cargo.toml`](../../Cargo.toml) workspace, has its own `todo/`, and holds
`fixtures/*.mjs` modules whose `fixtures/*.rs` twins `npm run gen` writes with
`fjs compile`. [`src/lib.rs`](../src/lib.rs)'s module comment is the only
description of what it is: the MVP walking skeleton that evaluates a compiled
module and prints it as JSON.

With no README and no rules of its own, a contributor cannot tell:

- that the `.rs` fixtures are generated, and are refreshed by `npm run gen`
  rather than edited;
- which Rust rules apply — [nanvm-lib/AGENTS.md](../../nanvm-lib/AGENTS.md)
  is scoped to `nanvm-lib/`, though `cargo test`, `cargo clippy` and
  `cargo fmt` run over the whole workspace;
- what the fixtures are for, and where a new one goes.

What a new fixture needs is two edits nobody lists — a `fjs compile` in
`package.json`'s `gen` and a `#[path]` module in `src/lib.rs` — and two
fixtures show the cost. `fixtures/function.mjs` and `rest-function.mjs` have
committed `.rs` outputs marked "@generated by `fjs compile`", but `gen` does
not compile them and `src/lib.rs` does not include them, so the files are
neither drift-checked nor built.
