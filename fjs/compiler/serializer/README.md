# Public output APIs

Source modules, evaluated runtime values and code-only function text now use
one output pipeline: admitted EDAG → normalized FAST → common preparation →
JavaScript syntax. Rust uses the same conversion and preparation with its own
prepared serializer. The public source wrappers retain their existing result,
chunk and marked-text APIs. They run source-spelling admission once after common
placement; runtime value output accepts its wider evaluated-value domain.

Source logical operators are normalized to single-evaluation conditionals by
AST-to-FAST sugar. Normalized/prepared FAST and canonical EDAG contain no
`&&`, `||` or `??` operation. Checked graph inputs reject those former tags;
the serializers spell the conditional form and provide no legacy graph adapter.
This intentionally changes graph structure, hashes and function text while
preserving source semantics and stable canonical round trips.

The common stages own evaluation regions, established captures, shared identity,
lazy memo storage and loop reconstruction. These wrappers select an output form;
they contain no target-specific graph placement algorithm. See
[`edag/to_fast`](../../edag/to_fast/README.md) for conversion, normalization and
the exact graph round-trip domain, and
[`js/ast/serializer`](../../js/ast/serializer/README.md) for JavaScript syntax.

Generated bytes intentionally follow the prepared serializer's canonical
spelling. Names, grouping, single-use temporaries and function-body aliases can
change from the former direct graph writers. Runtime `functionText` therefore
has a new canonical code spelling while retaining code-only behavior: capture
slots keep positional external names, captured values are neither rendered nor
evaluated, and function arity, rest parameters, self identity, lazy behavior and
failure behavior remain represented. Text stabilizes after normalization; raw
pre-FAST graph hashes and the old code bytes are not compatibility promises.

Named scalar loop functions establish capture aliases in signature order before
the condition. This removes the former inline writer's capture-order refusal
using the existing source grammar.

General fixed-parameter tail calls use loops in code-only JavaScript and Rust.
Source output retains rest-free canonical invocation roots recognized by the
shared scalar or plain-loop plan, plus one-input/one-result structured loops
whose loop transfers target their nearest loop and whose regions the source
grammar admits. Their returns retain the enclosing function owner, and statement
throws retain their reached evaluation and failure propagation. This includes
aggregate helpers for zero or multiple source state values. Common preparation
emits ordinary `while` statements; the plain-loop
plan computes its normal result after the final false test. The structured
source profile shares one physical state/result slot, spelling `break` and
`continue` without labels. Rest-free zero-input roots without a break to their
own target also retain bounded-stack source loops. They need no state or result
storage; shared preparation supplies the source grammar's unreachable terminal
return after a diverging loop. The first source parse introduces the ordinary
aggregate helper and may change graph bytes/hashes; its graph and canonical
text then stabilize. Reached work and capture lifetimes stay in their existing
regions. Other canonical invocation roots retain recursive source spelling
through the existing transfer resolver. The adapter repeats no
graph placement or tail eligibility analysis; required function owners retain
recursive names where needed.

The shared plain-loop plan also admits rest-free zero-input roots with a normal
result. Either conditional arm may continue; the other supplies the result
after the final test. Common preparation uses a private unchanged slot, keeping
the public function's empty parameter list and result computations outside
iteration. Parsing that first source introduces the canonical scalar helper,
and its normalized graph and text then stay exact. Condition-only definitions
run at every test; only identity-free projection dependencies may be copied
into the step or result. Other zero-input normal-result shapes retain their
existing recursive fallback.

Source preparation returns a refusal when a newly factored terminal recipe
requires normally completing guards outside the admitted one-input/one-result
loop profile. Raw zero-input roots outside the plain-loop plan, multi-input and
observed-rest graphs keep their existing reifiable recursive forms; unsupported
factored profiles return an error instead of asserting or emitting unreadable source.

The plain-loop spelling separates iteration from normal-result computation.
Parsing its first output can therefore introduce a scalar helper boundary and
change graph bytes/hashes. That source-normalized graph and its canonical text
stabilize on subsequent conversions without accumulating helpers or projection
demands. Existing canonical scalar-loop cases keep their exact graphs and source
spelling. Condition-only required prefix work can now use an ordinary `while`
where output previously used recursion or the general labelled loop.

Discarded literal `undefined` anchors also normalize away during graph
construction. They perform no failing work and create no identity; keeping them
would accumulate unused declarations when source branch-result slots are
reparsed. A supplied graph containing such an anchor can change its bytes/hash
on the first source parse. The normalized graph and text then remain exact.
Used `undefined` values, allocations, calls and other required work keep their
existing behavior and identity. The generated round-trip law classifies only
non-final literal `undefined` anchors with its other redundant prefixes.

Missing, extra and spread tail arguments normalize to fixed invocation inputs.
Parsing the first source output can inline one-use argument setup; serialization of the
normalized graph has that canonical spelling and reaches a source fixed point.
This initial graph/text migration preserves evaluation and source admission;
the existing exact-graph source domain keeps its round-trip checks.

Rest invocation loops use the shared fresh-rest argument recipe. Internal rest
state does not add a public fixed parameter. Source reconstruction restores the
original argument list instead of retaining private argument-vector wrappers,
preserving fresh rest identity and stable normalized graphs. Default and
destructuring setup lowered into the function body runs each iteration.

Source output continues to refuse frame layouts and lazy graphs the parser
cannot represent. The existing source proofs retain every graph fixture and
check graph normalization, text fixed points and agreement between token marks
and tokenization in addition to representative exact output strings.

The shared return pass forwards the sole result of an immediately returned
statement region into its normal leaves before graph construction. Terminal
source guards and switches containing loop returns therefore keep their reached
values within the selected region, without introducing source memo storage.
