# Public output APIs

Source modules, evaluated runtime values and code-only function text now use
one output pipeline: admitted EDAG → normalized FAST → common preparation →
JavaScript syntax. Rust uses the same conversion and preparation with its own
prepared serializer. The public source wrappers retain their existing result,
chunk and marked-text APIs. They run source-spelling admission once after common
placement; runtime value output accepts its wider evaluated-value domain.

Source logical operators are normalized to single-evaluation conditionals by
AST-to-FAST sugar. Normalized/prepared FAST and canonical EDAG contain no
`&&`, `||` or `??` operation. Checked graph inputs reject those former tags;
the serializers spell the conditional form and provide no legacy graph adapter.
This intentionally changes graph structure, hashes and function text while
preserving source semantics and stable canonical round trips.

The common stages own evaluation regions, established captures, shared identity,
lazy memo storage and loop reconstruction. These wrappers select an output form;
they contain no target-specific graph placement algorithm. See
[`edag/to_fast`](../../edag/to_fast/README.md) for conversion, normalization and
the exact graph round-trip domain, and
[`js/ast/serializer`](../../js/ast/serializer/README.md) for JavaScript syntax.

Generated bytes intentionally follow the prepared serializer's canonical
spelling. Names, grouping, single-use temporaries and function-body aliases can
change from the former direct graph writers. Runtime `functionText` therefore
has a new canonical code spelling while retaining code-only behavior: capture
slots keep positional external names, captured values are neither rendered nor
evaluated, and function arity, rest parameters, self identity, lazy behavior and
failure behavior remain represented. Text stabilizes after normalization; raw
pre-FAST graph hashes and the old code bytes are not compatibility promises.

Named scalar loop functions establish capture aliases in signature order before
the condition. This removes the former inline writer's capture-order refusal
using the existing source grammar.

General fixed-parameter tail calls use loops in code-only JavaScript and Rust.
Source output reifies nonscalar canonical invocation loops as recursion using
the existing root transfer resolver, then performs source admission. This keeps
previously supported source round trips while broader loop syntax waits for H;
it does not repeat graph placement or tail eligibility. Required function owners
remain in the common plan so the source recursive name is established.

Missing, extra and spread tail arguments normalize to fixed invocation inputs.
Parsing the first source output can inline one-use argument setup; serialization of the
normalized graph has that canonical spelling and reaches a source fixed point.
This initial graph/text migration preserves evaluation and source admission;
the existing exact-graph source domain keeps its round-trip checks.

Source output continues to refuse frame layouts and lazy graphs the parser
cannot represent. The existing source proofs retain every graph fixture and
check graph normalization, text fixed points and agreement between token marks
and tokenization in addition to representative exact output strings.
