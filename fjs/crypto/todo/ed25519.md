## Ed25519 signature verification

**Priority:** P3
**Status:** open

### Problem

FunctionalScript has secp256k1 ([`secp/`](../secp/module.f.js)), ECDSA
([`sign/`](../sign/module.f.js)), SHA-2 and HMAC, but no Ed25519, the
signature scheme of OpenSSH keys and so of SSH-signed Git commits. A consumer
that verifies such a commit has to reach for the host's WebCrypto: the check
becomes a host module with an asynchronous answer, its proofs are host proofs
that `fjs t` does not load, and the same code needs a host crypto API in
every runtime.

Verification needs no secret, so nothing about it requires the host:
it is arithmetic over the prime field `2²⁵⁵ − 19` and SHA-512, which
[`sha2/`](../sha2/module.f.js) already has.

### Proposal

A pure `fjs/crypto/ed25519/` module whose main export is RFC 8032 §5.1.7
verification:

```js
verify(publicKey)(message)(signature) // boolean
```

with the 32-byte public key, the message and the 64-byte signature as byte
vectors. The pieces:

1. **Square root mod `p`.** `prime_field`'s `sqrt` refuses a prime that is not
   `≡ 3 (mod 4)`, and `2²⁵⁵ − 19 ≡ 5 (mod 8)`. Add the `p ≡ 5 (mod 8)` case
   (RFC 8032 §5.1.3: a candidate root, corrected by `√−1` when its square is
   `−u/v`) to [`prime_field`](../../types/prime_field/module.f.js), refusing
   a non-residue with `null` as the existing `sqrt` does.
2. **Edwards arithmetic.** The twisted Edwards curve
   `−x² + y² = 1 + d·x²·y²`: addition and doubling in extended coordinates
   (RFC 8032 §5.1.4), so a scalar multiplication costs one inversion at the
   end rather than one per step, and scalar multiplication over them.
3. **Decoding** (RFC 8032 §5.1.3): a point from 32 little-endian bytes, the
   high bit the sign of `x`. Refuse `y ≥ p`, a `y` with no `x`, and `x = 0`
   with the sign bit set, so every point has one encoding.
4. **Verification** (RFC 8032 §5.1.7): refuse `S ≥ L`, decode `A` and `R`,
   refuse an `A` of small order (one of the eight points `P` with
   `[8]P = 0`), `k = SHA-512(R ‖ A ‖ M) mod L`, and check `[S]B = R + [k]A`.

**The equation is the cofactorless one**, rather than the cofactored
`[8][S]B = [8]R + [8][k]A` the RFC also permits. The two differ only on
signatures with a small-order component, which no honest signer makes.
OpenSSH has two verifiers, so "OpenSSH's rule" names none: Git verifies SSH
signatures with `ssh-keygen -Y verify`, and an OpenSSH built against an
OpenSSL with Ed25519 — the usual distribution package — hands the check to
OpenSSL ([`ed25519-openssl.c`](https://github.com/openssh/openssh-portable/blob/master/ed25519-openssl.c)),
which is cofactorless, as is the RFC 8032 reference implementation. An
OpenSSH built without it uses its libsodium-derived
[`ed25519.c`](https://github.com/openssh/openssh-portable/blob/master/ed25519.c),
which refuses small-order `A` and `R` and then accepts when
`R − ([S]B − [k]A)` has small order: cofactored, so it also accepts some
crafted signatures with a mixed-order `R` that this module refuses.

The small-order `A` refusal is not for compatibility: with such a key, one
signature can verify for many messages, and the cofactorless equation alone
does not prevent that. Record both choices in the module's JSDoc.

Signing and key generation are out of scope: they need secret keys, which a
host keeps (a browser's non-extractable WebCrypto key, for instance), and
their constant-time concerns do not apply to verification of public data.

### Tasks

- [ ] `sqrt` for `p ≡ 5 (mod 8)` in `prime_field`, with its proof.
- [ ] `fjs/crypto/ed25519/`: curve constants, extended-coordinate addition
  and doubling, scalar multiplication, point decoding, `verify`.
- [ ] Proof: the RFC 8032 §7.1 Ed25519 test vectors (the empty, 1-byte,
  2-byte, 1023-byte and `SHA(abc)` messages) verify; a flipped bit in the
  message, `R` or `S` does not; `S ≥ L`, a non-canonical `y`, a `y` with no
  `x`, `x = 0` with the sign bit set, and a small-order `A` are refused; a
  signature whose `R` is an honest `R` plus a small-order point (re-signed
  with the secret key so the cofactored check accepts it) is refused, which
  pins the cofactorless rule.
- [ ] List `ed25519/` in [`fjs/crypto/README.md`](../README.md).
