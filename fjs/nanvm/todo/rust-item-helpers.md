## The Rust generators spell their own tables, headers and quotes

**Priority:** P3
**Status:** open

### Problem

Several generators under `fjs/nanvm` and `fjs/compiler` write Rust items by
hand, line by line, and the same few items are spelled at each:

- **A `const` slice.** [`commands`](../commands/module.f.mjs)'s `generate`,
  [`methods`](../methods/module.f.mjs)'s `table` and
  [`harness`](../harness/module.f.mjs)'s `expectedModules` each write
  `#[rustfmt::skip]`, `pub const NAME: &[T] = &[`, one row per element and
  `];`.
- **The `@generated` header.** `commands`, `methods`, `harness`'s
  `modules`, [`rust`](../rust/module.f.mjs)'s `header` and
  [`compiler/rust`](../../compiler/rust/module.f.mjs)'s module each write
  generation provenance and an edit instruction. `commands`, `methods`
  and `nanvm/rust` put `// @generated by …` and `// Do not edit: …` on
  separate lines; `harness` and `compiler/rust` combine them on one line.
- **String rows without the escaper.** The rows are interpolated as
  `"${command}"`, `("${type}", "${method}")` and `name: "${name}"`, while
  [`fjs/media/rust`](../../media/rust/module.f.mjs) owns `stringLiteral`
  — which escapes, and refuses a lone surrogate — and `nanvm/rust` already
  uses it for the same job. A command or method name holding a quote
  would be written as Rust that does not compile.

[`fjs/media/rust`](../../media/rust/module.f.mjs) owns literal spelling
and its doc leaves expressions and items to each generator.
[let-bindings-owner](../../edag/rust/todo/let-bindings-owner.md) keeps
`Exp`-dependent bindings in
[`fjs/edag/rust`](../../edag/rust/module.f.mjs). That printer imports the
EDAG layer and `compiler/serializer`, so a const table importing from it
would make `nanvm/commands`, which imports only `effects/node` today, a
consumer of the whole graph machinery for the sake of some quoted rows.
The items these generators share need no `Exp`: they are spelled over
strings, one layer above the literals and below any printer. Nothing owns
that layer, so each generator is its owner.

### Proposal

An item module beside the literals, `fjs/media/rust/item/module.f.mjs`,
that imports `fjs/media/rust` and nothing of the EDAG: the layer of Rust
items spelled over strings. Its first two exports are
`constSlice(doc, name, type, rows, formatRow)` and
`generatedHeader(source, instruction)`. Literal spelling stays in
`fjs/media/rust`, whose doc sentence leaving items to the generator is
amended to name the sibling. Items that take an `Exp` — the `let` line
`let-bindings-owner` proposes — stay with the printer in `fjs/edag/rust`;
its string-level `skipFn`, if retained by that issue, belongs to this item
module too.

The indentation moves with the items. `indent`, the one level of
generated Rust, is exported by `fjs/edag/rust` today and imported by
`nanvm/rust` and `compiler/rust`; the item module cannot reach it without
importing the printer, and spelling the four spaces again would add the copy this issue
exists to remove. So `indent` is defined in the item module, and
`fjs/edag/rust` imports it from there — the printers that import it today
follow, or keep importing through `fjs/edag/rust`, which is a re-export
either way.

`constSlice` owns the documentation, annotation, declaration, row order,
indentation, commas and closing line. Rows keep the caller's own type;
`formatRow(row)` returns a `Result<string, E>` containing one Rust element
expression, without indentation or a trailing comma. The helper returns
`Result<string, E>`: the complete slice or the formatter's refusal.

The generators own their row formatters: a command string, a pair of type
and method strings, or a harness `Case` row. Each formatter calls
`stringLiteral` for its string fields, so an unescapable name is refused.
The harness row keeps its display name separate from its Rust module
identifier: quote `name`, but emit the `fixture`, `expected`, `json` and
`throws` references as code, using the harness's existing module naming.

`commands.generate()` and `methods.generate()` keep their no-argument,
string-returning APIs: unwrap each `constSlice` result with
[`types/result.unwrap`](../../types/result/module.f.mjs) while composing
the module text. A refused row throws its error, as `nanvm/rust`'s
`nameLiteral` already does; it is never dropped or coerced into Rust text.
Command and method names are authored source. Their generated-output proofs
use those tables. Synthetic escaping and refusal cases belong to
`stringLiteral` and `constSlice`'s public formatter input.

The harness reads live fixture filenames through `fixtures`, so its effect
boundary handles row refusal as input failure. A private, shared composer
returns the expected module text as a `Result`; the exported
`expectedModules(names)` keeps its string API by unwrapping that result.
`generateExpected` consumes the composer's result directly, converting a
refusal to `pureError(ioError({ message: ... }))` in its existing `IoChannel`,
with a diagnostic identifying the refused fixture name. It constructs the
`writeUtf8File` effect for `gen.expected/mod.rs` only on success. Earlier
per-fixture writes may already have completed; no rollback is required.
Loading, interpreting and writing failures keep their existing behavior.

The listed generators call the item helpers. The header helper may
standardize the comment-line layout; preserve each caller's generation
provenance and edit instruction, and the generated Rust's behavior.

`generatedHeader` returns plain header comment text; the caller supplies
separating blank lines. `compiler/rust`'s `generateTagged` wraps that text
with `tagged('comment')(generatedHeader(source, instruction))` before
composing the module. The caller keeps syntax marking: `toRustMarked`
and the Rust demo retain the header's `comment` kind, with separating
blank lines outside the mark.

### Tasks

- [ ] The item module with `indent` and the two helpers and a proof at
      100%, including row order and propagation of a row formatter's
      refusal; `fjs/edag/rust` importing `indent` from it; `fjs/media/rust`'s
      doc amended to name it.
- [ ] Retain `stringLiteral`'s quote, backslash and lone-surrogate proofs;
      exercise synthetic row refusals through `constSlice`'s `formatRow`
      input.
- [ ] Preserve the no-argument string APIs and authored-table output proofs
      for `commands.generate` and `methods.generate`.
- [ ] Keep `expectedModules(names)`'s string API and prove a lone-surrogate
      name throws. With valid module names, prove the `fixture`, `expected`,
      `json` and `throws` references remain unquoted.
- [ ] Prove the harness effect path reports the refused fixture name through
      `IoChannel` and never requests the `gen.expected/mod.rs` write; earlier
      per-fixture files may remain.
- [ ] Move the listed generators onto them; `npm run gen` and diff the
      generated files. Allow header-only layout changes and changes where
      a name needed escaping; preserve header content and generated Rust
      behavior.
- [ ] Preserve `compiler/rust`'s marked-output proofs: the header is marked
      as `comment`, the marked text equals `toRust`'s plain text, and the
      demo highlights the header as a comment. Update header text and run
      expectations only for the allowed layout changes.
- [ ] `tsc`, `fjs test`, `cargo test`.
