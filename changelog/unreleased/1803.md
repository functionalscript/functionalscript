- **BREAKING CHANGES:** `ci`: `packageCheckJob` is a `Job` rather than a
  `(pin: string) => Job`, and the generated `package-check` job no longer
  depends on the project at all. It used to appear only when the project's
  `package.json` pinned an exact `devDependencies.typescript`, and installed
  that compiler; the version is now `fjs/ci/config/module.f.mjs`'s, so the job
  is generated for every project and installs the configured one. A package
  that ships no declarations fails it with `TS18003` rather than not being
  checked. `fjs ci` no longer reads `package.json`.
- `ci`: TypeScript is provisioned by the environment instead of by `npm ci`.
  The `node26` and `dev` flakes carry `pkgs.typescript-go` — the pinned Nixpkgs
  snapshot's 7.0.2, whose `bin/tsc` is the same command every script already
  ran — and both jobs assert its version from inside their shell. `node22`,
  `node24`, `deno` and `bun` get no compiler: they run the suite and never open
  one. The generated Node 26 step is `tsc` rather than `npx tsc`.
- `typescript` is no longer a `devDependency` of this package, so `npm ci`
  installs one dependency, `@types/node`. Contributors take `tsc` from
  `nix develop ./nix/dev` or install the pinned version globally; `npx tsc`
  now resolves nothing locally and fetches the registry's latest, so it is no
  longer the way to type-check this repository. See `CONTRIBUTING.md`.
- The npm publish workflow installs the configured TypeScript before
  publishing. `npm publish` runs `prepack`, which runs `tsc`, so without it the
  publish would either fail on a missing compiler or emit the package's
  declarations with whatever the runner image happened to carry.
