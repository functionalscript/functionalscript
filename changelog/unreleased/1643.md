- **BREAKING CHANGES:** `protocol/mcp`, `cas/evo`, `effects/node`: the last
  library types that answered a raw effect now answer an `Effect` with a `never`
  channel — `Handle`, `Step`, `toolsList`, `toolsCall`, `ToolEntry.handle`,
  `decodeRevisionBlob`, and the `Test` operation's callback. None of them is
  infallible: each performs effects that can fail and *absorbs* the failure into
  its own vocabulary — a JSON-RPC error response, an `isError` tool result, a
  `null`, a panic. `never` states that decision where a reader can disagree with
  it, which a raw effect could not.
- `cas`, `mcp`, `protocol/mcp`, `emergent_testing`: the proof mock runners
  answer an `Effect` too. Every one of them was generic in its payload
  (`<T>(e: RawEffect<O, T>) => …`), which is a *type parameter* rather than a
  payload shape, so it becomes `Effect<O, T, E>` and wraps nothing new. Two of
  them stop hand-rolling what a type already states: `fjs/mcp/cas`'s driver
  unwraps its `never` channel with `unwrap` instead of an indexed cast, and
  `fjs/protocol/mcp`'s `withState` reads an Io history, whose links hold `ok`
  values rather than results. The `emergent_testing` runners name
  `RunInstance` — the type `mockRun` already returns — instead of respelling
  it.
- `cas`: converting `addBigFile`/`addAndGetBigFile` to `ioStep` surfaced a
  cleanup that had never worked. Both chains ended in `rm(testDir)` whose
  result the raw `step` discarded, and the virtual filesystem cannot remove a
  non-empty directory, so the `rm` failed on every run unobserved. The cleanup
  is gone — each run interprets against a fresh `emptyState` — and both proofs
  now assert their chain's final result, which an error would otherwise
  short-circuit past silently.
- `effects`, docs: the four places that recorded *why* `RawEffect` survives no
  longer name "absorb points" as a second reason. That claim used the MCP
  handler as its clearest case, and this change converts exactly that handler —
  so `fjs/effects/types.ts`, `fjs/AGENTS.md` §3.4, `fjs/effects/io/README.md`
  and `fjs/effects/todo/io-effect-migration.md` said the opposite of the code.
  The payload count offered alongside the old argument is corrected in the same
  places: most of those were type parameters, not payload shapes.
- **BREAKING CHANGES:** `effects`: `RawEffect` is **deleted**, and
  `Effect<O, T, E>` is the representation — a `Pure` thunk yielding
  `Result<T, E>`, or a `Do` node. `Pure`, `Cont` and `Do` carry the channel;
  `Effect` and `NotImplemented` move from `effects/io/types.ts` to
  `effects/types.ts`. The two-name split was defended as *composition* against
  *representation*, on the ground that the representation is generic over its
  payload by definition. It is — but `Operation` requires a `Result` return, so
  that payload is *always* a `Result`, and the second name described no
  reachable case.
- **BREAKING CHANGES:** `effects`: one set of combinators instead of two.
  `effects/module.f.mjs` keeps only the representation and its interpreters —
  `pure`, `do_`, `match`, `partialMatch`, `runPure` — and its `step`, `mapStep`,
  `history`, `historyStep`, `foldStep` and `forEachStep` are gone. The Io
  versions were never alternatives to them but corrections of them: the raw
  `step` ran its continuation whether or not the previous effect failed, the raw
  `historyStep` carried each link's `Result` into the history rather than its
  value, and the raw `forEachStep` ran every item whatever each one answered.
  `resultStep` **is** the former raw `step`, now the layer's primitive with
  `step` and `catchStep` written in terms of it.
- `effects/io`: `resultMapStep` is new — the trailing projection over the whole
  `Result`, as `mapStep` is over the value. It is what the call sites that used
  the raw `mapStep` meant, and it says so: `mapStep` cannot change the error
  channel, `resultMapStep` replaces it, so a site that discards a failure is
  written as one that took both branches. `unwrapStep` now answers
  `Effect<O, T, never>` rather than a bare-payload effect — the panic empties
  the channel instead of leaving the layer.
- `effects`: `pure` takes the `Result` a `Pure` holds, and reads both channels
  off it with the new `OkOf` / `ErrOf`. Matching `Result<T, E>` directly cannot
  place a one-sided argument — `pure(ok(v))` would infer the error channel as
  `T` as readily as `never` — which is also why `resultMapStep` projects its
  output channels the same way. `pureOk` / `pureError` are unchanged.
- **BREAKING CHANGES:** `effects/node`: `All` answers each effect's whole
  `Result` (`OpResult<readonly Result<T, E>[]>`), the nesting `allOk` already
  collapsed; `RequestListener` answers `Effect<O, ServerResponse, never>`, the
  response frame being where a listener puts its failures; `NodeEffect<T>` takes
  a channel, defaulting to `IoChannel`. The async runners (`asyncRun`,
  `runNodeEffect`, `run`) and `RunInstance` answer `Result<T, E>` — an
  interpreter never separates the channels, since a runner hands a failed
  command back through the ordinary continuation.
- `effects`, docs: the JSDoc no longer refers in the present tense to
  combinators this release deletes — ten sites across `effects/io` described a
  raw `historyStep` that "cannot serve here" or a raw `forEachStep` that "runs
  every item". The reasoning is kept, in the past tense that makes it history
  rather than a pointer to a live function. `effects/types.ts` also stops
  claiming every operation "already returned `OpResult` or `IoResult`" when the
  `Result` constraint landed: the host operations did, the proofs' own
  operations did not and had to be rewritten by that same commit, and what the
  rule requires is a `Result` rather than either alias. `changelog/1642.md`
  carried the same claim and is corrected while still unreleased, as is
  `changelog/1636.md`, which announced `RawEffect` as a public type this
  release deletes — it was created and removed inside one unreleased window, so
  no published API is called that.
- `effects/io`: `resultMapStep` gains its own proofs — both branches reaching
  `f`, absorbing an error into a success and rejecting a success into an error,
  and both over a `Do` node including a failed one.
