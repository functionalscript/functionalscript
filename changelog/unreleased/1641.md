- `effects/node`: `IoChannel` names the standard IO error channel
  (`NotImplemented | IoError`), which was spelled out at 50 sites. `IoResult<T>`
  is now `Result<T, IoChannel>`. Same type throughout — an IO-touching effect
  says it fails the way node IO fails, so gaining a new way to do so no longer
  walks up every enclosing signature.
- **BREAKING CHANGES:** `cas/evo`: `Evo.add` and `Evo.revision` no longer nest a
  domain `Result` inside the effect's value. Both answer
  `Effect<…, T, EvoChannel>`, where `EvoChannel` is the new tagged `EvoError`
  or `NotImplemented`. A rejected revision now short-circuits `step` like any
  other failure, and `evoSummary` renders either case.
- **BREAKING CHANGES:** `effects/io`: `unwrapStep` takes a second argument, a
  `summary` for the channel it panics on. It was generic in the error type, so
  it compiled however far a channel widened and quietly enlarged what it
  crashed on; a renderer written for one channel does not accept a wider one,
  so that is now a compile error at the site that chose to panic. `errorSummary`
  is the renderer for the node channel.
