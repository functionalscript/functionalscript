- **BREAKING CHANGES:** `effects/node`: `FileStat` carries `isFile` beside
  `size`, so a caller can tell a regular file from a FIFO, a device or a socket
  before reading it — a read that reaches one never returns
- **BREAKING CHANGES:** `effects/node`: `Listen` takes the host to bind as a
  third, required argument — `listen(server, port, host)` — and answers an
  `IoResult`, so a bind failure such as `EADDRINUSE` comes back through the
  effect's channel instead of killing the process after the program has already
  reported success
- `effects/node`: an HTTP request body past the `Vec` cap is answered `413`
  without reaching the listener, and a listener that throws answers `500`;
  either used to end the whole server process through an unhandled rejection.
  Both close the connection, since neither has read the request to its end
- `effects/node/virtual`: `listen` answers with the listener carried by the
  `Server` handle it was given, so two servers in one program no longer collapse
  into the one created last
- `web`: new `fjs web [root] [port]` command serving a directory over HTTP on
  `127.0.0.1` — `index.html` for directory paths, `Content-Type` by extension,
  `Content-Length` on every response, and `400`, `404`, `405`, `413` and `500`
  for everything it cannot answer with a file. Dot-prefixed segments (`.env`,
  `.git/config`) and entries that are not regular files (a FIFO, a device) are
  answered `404`, a `405` carries the `Allow` header naming the methods that
  would work, every response carries `X-Content-Type-Options: nosniff`, and
  an empty `root` argument is the working directory rather than the file system
  root
- `media/type`: `detectPath` gives the `Content-Type` a file name implies, from
  its extension
- `effects/node/virtual`: the runner implements `createServer` and `listen`,
  answering requests queued in `State` — `forever` remains unimplemented
