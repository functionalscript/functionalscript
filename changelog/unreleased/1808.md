- `ci`: the four non-Windows platform jobs run `cargo`, `npm ci` and
  `node --test` inside the shared Nix shell instead of installing a toolchain
  per runner. They are the only place the shell's `x86_64-linux` and Darwin
  outputs are built at all.
- `ci`: those jobs no longer install a published FunctionalScript and run
  `fjs test`; they run this commit's suite, as `deno` and `bun` already did.
  The published-CLI check survives on the two Windows jobs.
- `ci`: `ubuntu-intel32` is a new job, and the 32-bit Linux checks moved to it
  from `ubuntu-intel`. Its flake's `shellHook` points `cargo` at
  `pkgsi686Linux.stdenv.cc`, which cannot live in the shared shell.
- **BREAKING CHANGES:** `ci`: the `apt-get` `MetaStep` variant is removed. Its
  one producer installed a 32-bit libc that a Nix toolchain could not see, and
  no generated job asks the runner for a system package any more.
- `ci`: a `nodeExtra` step naming a command runs inside the shared shell on
  every platform but Windows, through `bash -e -c`, as GitHub runs a `run:`
  step. One declared as an `install` step moves too, losing its pre-checkout
  position.
- `ci`: an injected command reaches that shell in the step's `env`, as
  `FJS_CI_RUN`, so the generator adds no quoting of its own for a value GitHub
  substitutes to break out of.
- `ci`: a generated step may carry `env`; `stepSchema` admits it.
- `ci`: `rust/module.f.mjs` exports `i686Target`, the predicate deciding which
  platform jobs a shared shell cannot serve, and `rustPlatformCommands`, the
  native checks as commands rather than steps.
- **BREAKING CHANGES:** `media/nix`: an `_IndentedString` is its parts rather
  than one string — `['indented-string', ...(string | _Reference)[]]`. A
  `_Reference` part is written `${a.b}` for Nix to resolve. `NixJob`'s
  `shellHook` too.
- `media/nix`: indented strings escape every `'` as `''\'` and escape a `$`
  before an interpolation. Adjacent parts are joined first, so a reserved
  sequence cannot be synthesised across a boundary.
