- `ci`: `ubuntu-arm`, `macos-intel` and `macos-arm` run `cargo` and this
  repository's suite inside the shared Nix shell instead of installing a
  toolchain per runner. They are the only place the shell's `x86_64-linux`,
  `aarch64-darwin` and `x86_64-darwin` outputs are built rather than generated
  as text. `ubuntu-intel` runs in a flake of its own, whose `shellHook` points
  `cargo` at `pkgsi686Linux.stdenv.cc` for the 32-bit link its
  `i686-unknown-linux-gnu` checks need — a toolchain available on
  `x86_64-linux` alone, replacing `apt-get install libc6-dev-i386`, which a Nix
  toolchain could not have seen. Only the two Windows jobs still
  install a toolchain, because Nix has no native Windows.
- `ci`: those three jobs no longer install a published FunctionalScript and run
  `fjs test`; they run this commit's suite through `node --test`, as `deno` and
  `bun` already did. The published-CLI check survives on the two Windows jobs.
- `ci`: `rust/module.f.mjs` exports `i686Target`, the predicate deciding which
  platform jobs a shared shell cannot serve, and `rustPlatformCommands`, the
  native checks as commands rather than steps.
- **BREAKING CHANGES:** `media/nix`: an `_IndentedString` is its parts rather
  than one string — `['indented-string', ...(string | _Reference)[]]`. A string
  part is escaped as before; a `_Reference` part is written `${a.b}` for Nix to
  resolve, which is the only way a generated hook can name a store path.
  `NixJob`'s `shellHook` takes the same parts.
- **BREAKING CHANGES:** `ci`: the `apt-get` `MetaStep` variant is removed. Its
  one producer installed a 32-bit libc for `ubuntu-intel`, which now gets one
  from its flake, and no generated job asks the runner for a system package any
  more.
