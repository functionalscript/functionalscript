- **BREAKING CHANGES:** `media/json`: new `extended` codec — bare integer
  syntax parses to `bigint` and serializes back as ordinary JSON, `-0` stays a
  `number`, and out-of-range tokens are parse errors. `parser.parse` now takes
  a numeric policy, so standard and extended parsing share one state machine
- **BREAKING CHANGES:** `js/tokenizer`: a number token carries only its exact
  lexeme; the derived `bf` field is gone, so no valid number fails to tokenize
  because a coefficient or exponent exceeds a runtime numeric type
- `media/json`: new `number` module with bounded lexical helpers
  (`numberLexeme`, `isBareInteger`, `isIntegral`) that classify a token in its
  own length, without narrowing it or evaluating `10 ** exponent`
- `types/object`: `definedEntries` infers its value type from the record it is
  given, so a record whose value type is generic can be passed
