- **BREAKING CHANGES:** `ci`: TypeScript is provisioned by the environment
  rather than by `npm ci`. `typescript` is no longer a `devDependency`, so
  `npx tsc` resolves nothing locally and fetches the registry's latest — take
  the compiler from `nix develop ./nix` or a global install of the pinned
  version. `packageCheckJob` is a `Job` rather than a `(pin: string) => Job`,
  the `package-check` job is generated for every project, and `fjs ci` no longer
  reads `package.json`. (#1803)
- **BREAKING CHANGES:** `ci`: the generated jobs enter one shared Nix developer
  shell, generated to `nix/` itself. `denoNixJob`, `bunNixJob`, `wasmNixJob` and
  `basicNode` are gone, `nodeNixJobs` carries no default Node version, and
  `wasmRust`/`wasmPackages` replace `wasmNixJob`. `./nix/dev` no longer exists:
  the shell is `nix develop ./nix`, or `./dev.sh` at the repository root.
  (#1807, #1808, #1814)
- **BREAKING CHANGES:** `ci`: the `ci-update`, `dev-update` and `update` npm
  scripts are gone. `gen` covers the first two and needs no Nix; `lock-update`
  covers `update` and also refreshes every generated `flake.lock` and
  `Cargo.lock`. The generated `run` scripts pass `--no-update-lock-file`, so a
  stale lock now fails every command through them instead of resolving in memory
  and warning. (#1813, #1825, #1831)
- **BREAKING CHANGES:** `media/nix`: an `_IndentedString` is its parts rather
  than one string — `['indented-string', ...(string | _Reference)[]]` — and a
  `_Reference` part is written `${a.b}` for Nix to resolve. `NixJob`'s
  `shellHook` too. The `apt-get` `MetaStep` variant is removed. (#1808)
- **BREAKING CHANGES:** several public `types.ts` declarations gained `readonly`
  on tuple and object members — `bnf`'s `Option`, `types/range_map`'s `Entry`,
  and others. A value no longer fits a mutable-tuple slot, and mutating one or
  assigning through an object field now fails type checking. (#1822)
- **BREAKING CHANGES:** `bnf`: metadata is shared `Meta<M, T>` tuples. LL(1)
  inputs require them, `CodePointMeta` is removed, LL(1) result types gain `M`,
  and the map and RTTI types replace `MI` and `MO` with one `M`. `repeat` moved
  to `types/array` and returns a fixed-length tuple; the `Repeat` type is gone.
  (#1817, #1828)
- **BREAKING CHANGES:** `emergent_testing`: the browser runner moved to
  `emergent_testing/browser/module.mjs` and `unknownValue` to
  `emergent_testing/module.f.mjs`; no compatibility file is left behind.
  `startBrowserTestSources` takes no importer — a page's `import()` is an
  operation its interpreter answers — and `defaultReporter` answers
  `Reporter<Write | Sandbox | Catch>`, so a runner driving it must dispatch
  `catch`. (#1806, #1818, #1832)
- **BREAKING CHANGES:** `website`: the browser source scanner moved to
  `website/browser-source/module.f.mjs` and is FunctionalScript rather than
  plain `.mjs`; `exportsProof`, `specifiers` and `local` are unchanged.
  `website/browser-prepare.mjs` is removed — the proof manifest is generated by
  `website/module.f.mjs`, so the `website` script is
  `node ./fjs/module.mjs r ./fjs/website/module.f.mjs`. (#1824, #1827)
- **BREAKING CHANGES:** `effects/node`: `Dirent` gains `isDirectory`.
  `isFile === false` does not mean "directory" — a symbolic link is neither — so
  a runner implementing `Readdir` must return it, and a walk can ask what it
  needs before descending. (#1827)
- **BREAKING CHANGES:** `nanvm`: `Any + Any` returns `Result`, and `Unpacked` no
  longer implements `Add`. (#1811)
- `bnf`: reusable JSON and DataJS grammars, LL(1) semantic transformer maps that
  build values while parsing, and RTTI-checked rule mapping contracts that
  reject a mapping whose declared input type does not match the grammar.
  (#1817, #1823, #1828)
- `nanvm`: JavaScript-compatible addition and subtraction for VM values, with a
  shared TypeError message for mixed `number`/`bigint` arithmetic. Bigint string
  coercion produces JavaScript-compatible decimal text. (#1709, #1810, #1811)
- `effects`: `Import`, `Module` and `import_` moved to `effects/common`, `All`,
  `all`, `allOk` and `both` with them, and `errorMessage` to `effects` beside
  the channel it renders — operations with more than one implementer live there,
  and a browser page loads modules too. `effects/node` re-exports all of them,
  so importing through it is unchanged. (#1812, #1815, #1818)
- `emergent_testing`: `LeafReporter` — the three events a leaf produces
  (`start`, `result`, `test`) — splits out of `Reporter`, which is now that plus
  `summary`. `runEntries` takes the smaller one, so a host that ends its own run
  supplies no `summary`, and it has no error channel: every failure a leaf's
  chain meets is answered as `RunState.aborted`. (#1802)
- `emergent_testing`: `fjs t` survives what used to end it. A module whose
  `proof` export cannot be enumerated is reported as one failed record named for
  the module and the run continues; a thrown value whose `toString` throws is
  described as `Unknown thrown value` rather than killing the summary after
  every test has already run. (#1830, #1832)
- `emergent_testing`: the browser page renders a row for a test while it is
  running and settles that row when the test lands, so a proof that blocks no
  longer blocks with nothing on screen. `runBrowserProofs` takes an optional
  third argument, `start`; existing calls are unaffected. (#1840)
- `emergent_testing`: the browser page loads its proof modules one at a time, so
  its interpreter no longer implements `all` and a suite larger than the
  engine's call-argument limit is not a shape the runner can build. `reportOf`
  folds a browser run's results into its report. (#1809, #1818)
- `types`: `AbstractRequiredMap` describes a required-map API with an
  unrestricted string key set, and `StateFold` describes a fold with explicit
  initialization, state updates and finalization. (#1826)
- `website`: the browser proof manifest generator refuses a module read that
  failed for anything but a missing path, rather than reading an oversized
  module as importing nothing. `readFile`'s size-cap failure names the file it
  refused, on the Node runner and the virtual one alike. (#1842)
